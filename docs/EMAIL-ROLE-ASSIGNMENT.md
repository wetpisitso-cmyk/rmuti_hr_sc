# ADMIN — เพิ่มหรือกำหนดสิทธิ์ด้วยอีเมล

## วิธีใช้

1. เข้าสู่ระบบ rmuti_hr_sc ด้วยบัญชี ADMIN
2. เปิดเมนู **จัดการระบบและสิทธิ์** หรือเข้าที่ `#admin`
3. ช่อง **เพิ่มหรือกำหนดสิทธิ์ด้วยอีเมล** พิมพ์อีเมลมหาวิทยาลัย เช่น `name@rmuti.ac.th`
4. เลือก `USER` / `HR` / `ADMIN` แล้วกด **เพิ่ม / กำหนดสิทธิ์**
5. ตรวจยืนยันชื่ออีเมลและบทบาทก่อนบันทึก

## สถานะผลการบันทึก

- อีเมลที่ **ยืนยันแล้วและมีทะเบียน hr_members**: ระบบเปลี่ยนบทบาททันที และลงประวัติใน `hr_role_audit`
- อีเมลที่ **ยังไม่สมัคร หรือยังไม่ยืนยันอีเมล**: สำหรับ USER และ HR ระบบเก็บรายการรอไว้ 30 วัน; หลังสมัครและกดยืนยันอีเมลจากระบบ Auth ระบบตรวจรายการรอและเปิดสิทธิ์ตามบทบาทที่ ADMIN กำหนด
- สิทธิ์ ADMIN **ไม่เปิดให้สั่งล่วงหน้า**: เจ้าของอีเมลต้องยืนยันแล้วก่อน จึงกำหนด ADMIN ได้
- รายการรอมีปุ่ม **ยกเลิกรายการ** สำหรับ ADMIN; รายการหมดอายุจะไม่ถูกนำไปใช้
- ระบบนี้ **ไม่ส่งอีเมลเชิญเอง และไม่สร้างบัญชี Auth โดยอัตโนมัติ** เจ้าของอีเมลสมัครและยืนยันผ่านหน้าเว็บด้วยตนเอง

## ความปลอดภัย

- ฟังก์ชัน `hr_admin_assign_email`, `hr_admin_list_pending_email_roles`, `hr_admin_cancel_pending_email` ตรวจสิทธิ์ ADMIN ใน PostgreSQL
- จำกัดโดเมน `@rmuti.ac.th` และป้องกันการเปลี่ยนสิทธิ์ของ ADMIN ตนเอง
- ผู้สมัครทั่วไปไม่ได้รับ HR/ADMIN ด้วยการใส่ข้อมูล role ในฟอร์มสมัคร; จะได้รับ USER ตามปกติหากไม่มีรายการรอที่ ADMIN กำหนด
- การเปิดสิทธิ์ HR ที่รอไว้เกิดเฉพาะเมื่อบัญชี **ยืนยันอีเมลครั้งแรก** และผู้อนุมัติเดิมยังเป็น ADMIN
- บันทึกประวัติการยกบทบาท STAFF → HR จากรายการรอ
- ไม่เปลี่ยนสิทธิ์ของผู้ดูแลระบบเดิม และไม่ได้ลบข้อมูลบุคลากร

## ข้อควรทราบ

- ต้องตั้งค่า **Confirm email + SMTP + Redirect URL** ใน Supabase Auth และทดสอบส่งอีเมลจริงก่อนใช้งานวงกว้าง
- การมีอีเมลมหาวิทยาลัยยังไม่ใช่หลักฐานว่าเป็นบุคลากรปัจจุบัน ณ วิทยาเขตขอนแก่น ควรตรวจทะเบียนงานบุคคลก่อนแต่งตั้ง HR/ADMIN
