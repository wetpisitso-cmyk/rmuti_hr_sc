# ระบบเสนอเอกสาร ตรวจสอบ อนุมัติ และลงนาม (v1)

ระบบใหม่ทำงานแยกจากคำขอหนังสือรับรองเดิม เพื่อไม่แก้ไขข้อมูลหรือสถานะเดิม

## ขั้นตอน
1. ผู้เสนอ เข้าสู่ระบบ > ระบบเสนอเอกสารและลงนาม > ระบุเรื่องและเนื้อหา > เลือกผู้ตรวจสอบ ผู้อนุมัติ ผู้ลงนาม > เสนอเอกสาร
2. ผู้ตรวจสอบที่ได้รับมอบหมาย กด รายละเอียด > ตรวจสอบผ่าน / ส่งกลับแก้ไข / ไม่อนุมัติ
3. ผู้อนุมัติที่ได้รับมอบหมาย กด อนุมัติ / ส่งกลับแก้ไข / ไม่อนุมัติ
4. ผู้ลงนามเข้าสู่เมนู ลายเซ็นอิเล็กทรอนิกส์ เพื่อบันทึกลายเซ็น จากนั้นเปิดเอกสารที่รอลงนามและยืนยันลงนาม
5. ผู้เกี่ยวข้องเปิดเอกสารที่ลงนามแล้วและพิมพ์จากหน้าเว็บได้ พร้อมดูประวัติและ SHA-256 ของเนื้อหา

## สิทธิ์
- ผู้เสนอเป็นสมาชิกบุคลากรใน hr_members
- ผู้ตรวจสอบ ผู้อนุมัติ ผู้ลงนาม ต้องมี role=hr ใน hr_members
- ผู้เสนอ ผู้ตรวจสอบ ผู้อนุมัติ ผู้ลงนาม ต้องเป็นคนละบัญชี
- สถานะเปลี่ยนได้เฉพาะโดยผู้ที่ได้รับมอบหมายในขั้นนั้น ระบบใช้ Postgres functions ตรวจสอบสิทธิ์
- ผู้เกี่ยวข้องทั้งสี่คนเท่านั้นที่อ่านเอกสารและประวัติผ่าน RLS ได้
- ตารางประวัติไม่เปิดให้เบราว์เซอร์เขียนตรง
- ข้อมูลที่ลงนามเก็บ snapshot ลายเซ็น ณ เวลาลงนาม รวมถึง SHA-256 และเวลา

## ข้อจำกัดที่สำคัญ
- ต้องมีบัญชี HR 3 บัญชี และผู้เสนออีก 1 บัญชี (ปัจจุบันมี HR เพียง 1)
- ฉบับแรกเป็นเอกสารข้อความที่พิมพ์จากเว็บได้ ยังไม่มีระบบฝังลายเซ็นลง PDF ต้นฉบับบน Drive
- ลายเซ็นวาดด้วยเมาส์/นิ้วและการคลิกยืนยัน ไม่เทียบเท่าลายเซ็นดิจิทัลที่ใช้ใบรับรองและตรวจสอบย้อนกลับด้วย PKI
- ยังไม่มีบริการลงนามแบบยืนยันตัวตนซ้ำ (step-up authentication), การประทับเวลาโดยบุคคลที่สาม, หรือหนังสือราชการที่ออกจากเทมเพลตทางการ
- ต้องตรวจสอบด้านกฎหมาย ระเบียบสารบรรณ และกระบวนอนุมัติของมหาวิทยาลัยก่อนใช้เอกสารเป็นทางการ
- Edge Function Google Drive เดิมยังต้องตั้งค่า Service Account Secrets/ทดสอบก่อนรับเอกสารจริง
- ยังไม่เปิดรับไฟล์แนบต้นฉบับในเมนูเสนอเอกสารใหม่ เพื่อไม่อ้างว่ารองรับการลงนาม PDF แล้ว
