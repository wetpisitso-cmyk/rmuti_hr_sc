# คู่มือเปิดสมัครบุคลากรเองด้วยอีเมล @rmuti.ac.th

## ขอบเขต

* เปิดสมัครด้วยอีเมล `@rmuti.ac.th` และรหัสผ่าน **เฉพาะระบบ rmuti_hr_sc** ไม่ใช่ RMUTI SSO ของมหาวิทยาลัย
* ยืนยันเจ้าของอีเมลก่อนเปิดสิทธิ์ บุคลากรที่ยืนยันแล้วจะมีบทบาท `staff` อัตโนมัติ
* Admin/HR เดิมไม่ถูกลดสิทธิ์ ผู้ใช้สมัครเองไม่มีสิทธิ์ตั้งตัวเองเป็น HR
* ข้อมูลชื่อที่ผู้สมัครกรอกเป็น **ข้อมูลแจ้งด้วยตนเอง** ไม่ถือเป็นการรับรองว่าเป็นบุคลากรปัจจุบัน
* การครอบครองอีเมลของมหาวิทยาลัย **ไม่รับรองว่าเป็นบุคลากรวิทยาเขตขอนแก่น** หากต้องจำกัดเฉพาะบุคลากรปัจจุบัน ควรเชื่อมทะเบียนบุคลากร/ฐานข้อมูลกลุ่มผู้ใช้จากมหาวิทยาลัย (หรือกำหนดนโยบายยืนยันสิทธิ์แยกตามบริการ)

## เปิดใช้งาน Supabase Auth — ต้องทำใน Dashboard

Project: `kaqnnyexlojscvrlpoex`

1. Authentication → Providers → Email: **Enable email provider**, เปิด **Allow new users to sign up**, และเปิด **Confirm email / Enable email confirmations**
2. Authentication → URL Configuration:
   * Site URL: `https://wetpisitso-cmyk.github.io/rmuti_hr_sc/`
   * เพิ่ม Redirect URL: `https://wetpisitso-cmyk.github.io/rmuti_hr_sc/`
3. Authentication → SMTP Settings: ตั้ง **Custom SMTP** สำหรับส่งอีเมลจริง เพราะบริการ SMTP เริ่มต้นของ Supabase จำกัดการส่งไปยังอีเมลที่ไม่ได้อยู่ในทีมโปรเจกต์
4. Authentication → Security and Protection: เปิด CAPTCHA/การจำกัดการสมัครและการป้องกันรหัสผ่านหลุด (ถ้าแพ็กเกจรองรับ)
5. ห้ามปิดการยืนยันอีเมลเพื่อให้สมัครได้เร็วขึ้น — ทริกเกอร์ถูกออกแบบให้ไม่สร้างสมาชิก `staff` เมื่อไม่มีการส่งยืนยันอีเมลจริง

## ทดสอบ

1. เปิดเว็บไซต์ → **สมัครสมาชิกด้วยอีเมลมหาวิทยาลัย** ใส่ชื่อจริง นามสกุล อีเมลมหาวิทยาลัย และตั้งรหัสผ่าน (อย่างน้อย 10 ตัว)
2. ตรวจอีเมลมหาวิทยาลัย กดลิงก์ยืนยัน แล้วเข้าสู่ระบบด้วยอีเมล/รหัสที่ตั้งเอง
3. ยืนยันตาราง `auth.users`: `email_confirmed_at` ไม่เป็น NULL
4. ยืนยันตาราง `hr_members`: ผู้ใช้ใหม่มี `role='staff'` เท่านั้น
5. ยืนยันตาราง `hr_profiles`: มีเฉพาะข้อมูลตนเองและแก้ไขชื่อ/role ผ่านหน้าบ้านไม่ได้
6. ตรวจด้วยบัญชี staff ว่าเข้าเมนู HR ไม่ได้ และอ่านข้อมูลบุคลากรอื่นผ่าน API ตรงไม่ได้
7. ทดลองสมัคร `@gmail.com`: หน้าเว็บต้องปฏิเสธ และไม่มีสิทธิ์ในฐานข้อมูล
8. ทดลองสมัครแล้ว **ยังไม่กดยืนยันอีเมล**: ต้องไม่เกิดสมาชิกใน `hr_members`
9. ทดลองลืมรหัสผ่าน: ลิงก์ตั้งรหัสผ่านใหม่ต้องส่งกลับมายังเว็บนี้ และผู้ใช้ต้องตั้งรหัสผ่านใหม่ได้
10. ก่อนเปิดให้ใช้งานจริง ควรทดสอบยืนยันอีเมลกับ SMTP จริงอย่างน้อย 1 บัญชีโดยไม่ใช้ข้อมูลบุคลากรที่อ่อนไหว

## ความปลอดภัย

* RLS ฝั่งฐานข้อมูลตรวจบทบาทจาก `hr_members` (ไม่เชื่อ `user_metadata`)
* `hr_internal.is_member()` และ `is_hr()` ตรวจว่าอีเมลมหาวิทยาลัยถูกยืนยัน
* Account ที่ยืนยันแล้วหลังสมัครได้รับ `staff` เท่านั้น
* ฟังก์ชันเสนอ/อนุมัติเอกสารตรวจสมาชิกมหาวิทยาลัยอีกชั้น
* Edge Function ดึง PDF จาก Google Drive ตรวจอีเมลมหาวิทยาลัยและการยืนยันก่อนจัดการเอกสาร
* ไม่มีรหัสผ่าน/Service Role ในโค้ดเว็บไซต์หรือ GitHub
* ฟังก์ชัน Google Drive ยังต้องตั้งค่า Service Account Secrets และทดสอบการอัปโหลด/ดาวน์โหลดจริงแยกต่างหาก

## ข้อควรระวัง

การสมัครได้ด้วยตนเองไม่ได้หมายความว่าเจ้าของบัญชีมีอำนาจ HR, เป็นผู้อนุมัติเอกสาร หรือเป็นบุคลากรวิทยาเขตขอนแก่นจริง การพิสูจน์ว่าเป็นบุคลากรปัจจุบันต้องเทียบกับทะเบียนอย่างเป็นทางการ และสำหรับเอกสารราชการควรดำเนินการตรวจสิทธิ์เพิ่มเติมก่อนให้ดูข้อมูลภายในที่มีความลับ
