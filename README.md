# rmuti_hr_sc — ระบบสารสนเทศบุคลากร มทร.อีสาน วิทยาเขตขอนแก่น

**โครงการใช้งานจริง:** โปรดอ่าน `docs/DEPLOY-RMUTI-HR-SC.md` ก่อนเปิดใช้

- GitHub Pages: หน้าเว็บ HTML/CSS/JS ธีมน้ำเงิน–ส้ม–ขาว พร้อม Noto Sans Thai
- Supabase Project `rmuti_hr_sc`: Auth, PostgreSQL, ระบบ RLS (สร้างฐานข้อมูลแล้ว)
- Google Drive: เก็บ PDF จริง; Supabase เก็บรหัสอ้างอิงไฟล์เท่านั้น
- Supabase Edge Function `hr-drive-document`: ติดตั้งแล้ว แต่ยังต้องกำหนด Google service account Secrets และให้สิทธิ์โฟลเดอร์
- อัปโหลดผ่านฟังก์ชันเฉพาะเจ้าหน้าที่ HR; ดาวน์โหลดโดยเจ้าของคำขอที่พร้อมรับหรือเจ้าหน้าที่ HR

**ข้อจำกัด:** สร้าง GitHub repository `rmuti_hr_sc` แล้ว แต่ยังไม่มีบัญชีผู้ใช้งานจริง และยังไม่ได้ทดสอบส่ง PDF ขึ้น Google Drive จริง บัญชี Google Service Account ต้องมีสิทธิ์เขียนในพื้นที่จัดเก็บที่รองรับ (ควรใช้ Shared Drive ของมหาวิทยาลัยสำหรับการอัปโหลดผ่าน service account)

เอกสาร README ต้นฉบับของ ZIP อธิบายโหมดทดลองที่ใช้ localStorage และการใช้งานหน้าต่าง ๆ หากต้องการทดสอบตัวอย่างแบบออฟไลน์ให้แก้ `web/config.js` กลับเป็น `mode: 'demo'` ชั่วคราว; ค่าเริ่มต้นของชุดนี้เป็น `mode: 'supabase'` และต้องล็อกอินจริง

# ระบบสารสนเทศบุคลากร มทร.อีสาน วิทยาเขตขอนแก่น

สำหรับแผนกงานบริหารงานบุคคล มหาวิทยาลัยเทคโนโลยีราชมงคลอีสาน วิทยาเขตขอนแก่น

หน้าเว็บใช้ฟอนต์ **Noto Sans Thai** ผ่าน Google Fonts (ต้องเชื่อมต่ออินเทอร์เน็ตเพื่อโหลดฟอนต์) และมีไฟล์ใบอนุญาต OFL ที่ `web/fonts/OFL.txt`

## เปิดใช้ตัวอย่างใน 1 นาที

1. แตกไฟล์ ZIP ทั้งโฟลเดอร์ก่อนเปิด
2. เปิด `web/index.html` ด้วย Chrome หรือ Microsoft Edge บนคอมพิวเตอร์
3. ระบบจะเปิดหน้าข้อมูลส่วนตัวด้วยบัญชีบุคลากรสมมติ เลือกคณะ หน่วยงาน และสังกัด แล้วกด **บันทึกข้อมูล**
4. กด **สลับบทบาท** ที่มุมขวาบนเพื่อทดลองเป็นเจ้าหน้าที่ HR ปุ่มนี้ใช้เฉพาะโหมดทดลอง

ชุดนี้เปิดบนเครื่องได้ทันที ไฟล์หน้าจอ สไตล์ และไลบรารีอยู่ในโฟลเดอร์เดียวกันทั้งหมด โหมดทดลองใช้ข้อมูลสมมติและบันทึกในพื้นที่ของเบราว์เซอร์เดิมบนเครื่องนั้น บทบาททั้งสองใช้ข้อมูลทดลองชุดเดียวกันเพื่อให้ลองส่งงานถึงกันได้ ใช้ข้อมูลสมมติสำหรับโหมดนี้ การล้างข้อมูลเว็บไซต์หรือเปลี่ยนเบราว์เซอร์จะทำให้เริ่มชุดตัวอย่างใหม่ได้ สำหรับการเปิดผ่านไฟล์ พฤติกรรมการเก็บข้อมูลขึ้นกับเบราว์เซอร์ หากเครื่องจำกัดการเปิดไฟล์ ให้ใช้วิธี localhost ด้านล่าง

## ลองกระบวนงานที่สำนักงานจะใช้จริง

| ผู้ทดลอง | ขั้นตอน | สิ่งที่ควรเห็น |
| --- | --- | --- |
| บุคลากร | ขยาย **ระบบขอหนังสือรับรอง** เลือก **หนังสือรับรองเงินเดือน** กรอกวัตถุประสงค์และจำนวน กด **ยื่นคำขอ** | กลับหน้าสรุป เห็นเลขคำขอ HR-xxxxx และสถานะส่งคำขอแล้ว |
| เจ้าหน้าที่ HR | กด **สลับบทบาท** เลือกเจ้าหน้าที่ เข้า **งานเจ้าหน้าที่ HR** เปิดรายละเอียด เลือก **กำลังตรวจสอบ** และบันทึก | สถานะในคิวงานเปลี่ยน |
| เจ้าหน้าที่ HR | เปิดรายการเดิม เลือก **พร้อมรับเอกสาร** ระบุจุดรับหรือวิธีรับ สามารถแนบ PDF ที่เจ้าหน้าที่จัดทำเสร็จแล้ว | ข้อความส่งถึงผู้ยื่นและมีไฟล์เมื่อแนบ PDF |
| บุคลากร | สลับกลับเป็นบุคลากร ไปที่ **สรุปข้อมูลการขอหนังสือรับรอง** แล้วเปิดรายละเอียด | อ่านข้อความ พิมพ์ใบรับคำขอ A4 หรือดาวน์โหลด PDF ที่ HR ส่งให้ |
| เจ้าหน้าที่ HR | เมื่อส่งมอบเอกสารแล้ว เลือก **รับเอกสารแล้ว** | ปิดรายการโดยเก็บรายละเอียดไว้ดูย้อนหลัง |

กรณีเอกสารไม่ครบ เจ้าหน้าที่เลือก **ส่งคืนคำขอ** และระบุเหตุผล บุคลากรอ่านเหตุผลจากรายละเอียดและยื่นคำขอใหม่ได้ คำขอหนังสือสัญญาจ้าง ก.พ. 7 ใช้ขั้นตอนเดียวกัน ไฟล์แนบฉบับทดลองรองรับ PDF ขนาดไม่เกิน 512 KB ต่อไฟล์ ส่วนโหมด Supabase รองรับ 5 MB ต่อไฟล์

## ส่วนที่สร้างจากภาพ และส่วนที่ออกแบบสำหรับขอนแก่น

ใช้ภาพอ้างอิง 3 ภาพของผู้ขอเป็นหลักสำหรับลำดับเมนู โครงสร้างแถบนำทาง เมนูย่อย หน้าข้อมูลส่วนตัว และตัวเลือกสังกัดที่สัมพันธ์กัน 4 ระดับ หน้าภายในของเว็บไซต์อ้างอิงเปิดตรวจสอบไม่ได้ ซอร์สชุดนี้เขียนใหม่ กระบวนงานอนุมัติ บทบาท HR แบบบันทึกผลงาน และรายงานเป็นแบบที่จัดทำเพื่อทดลองกับวิทยาเขต เจ้าของงานสามารถปรับให้ตรงระเบียบก่อนใช้งานกับบุคลากรจริง

| เมนู | ใช้ทำอะไรได้ |
| --- | --- |
| หน้าหลัก | ดูจำนวนคำขอระหว่างดำเนินการ เอกสารพร้อมรับ กิจกรรมที่ลงทะเบียน และคำขอล่าสุดของตน |
| ข้อมูลส่วนตัว | ตรวจชื่อจากทะเบียนบุคลากร แก้ข้อมูลการปฏิบัติงาน เลือกสังกัด วาด/แก้ลายเซ็น ดูครุภัณฑ์ สิทธิ์ และส่งผลประเมินระบบ |
| ระบบขอหนังสือรับรอง | ยื่นคำขอ 2 ประเภท ติดตามผล พิมพ์ใบรับคำขอ และดาวน์โหลดฉบับที่ HR แนบ |
| ระบบสืบค้นคำสั่ง | เปิดคำสั่งทั่วไปหรือเฉพาะบุคคล ค้นเลขที่ เรื่อง และข้อความ ฝ่าย HR เผยแพร่คำสั่งจากหน้าจอได้ |
| ระบบลงทะเบียนกิจกรรม | ดูเวลา สถานที่ จำนวนที่นั่ง สมัคร ยกเลิกก่อนเริ่ม ดูประวัติรายการที่ยังลงทะเบียน เจ้าหน้าที่ดูรายชื่อผู้เข้าร่วมได้ |
| ระบบประเมินผลการปฏิบัติราชการ | ส่งสรุปผลงานหนึ่งครั้งต่อคนต่อรอบ หรือไปยังระบบประเมินทางการเมื่อกำหนดลิงก์ |
| งานเจ้าหน้าที่ HR | จัดการคำขอ เผยแพร่คำสั่ง เปิดกิจกรรม มอบครุภัณฑ์ ดูผู้ลงทะเบียน ผลประเมินระบบ และสรุปผลงาน |
| ระบบอื่น ๆ และเมนูช่วยเหลือ | คู่มือย่อ หน่วยงานติดต่อ และช่องกำหนดลิงก์บริการ นโยบาย และข้อกำหนดฉบับอนุมัติ |

ลายเซ็นเป็นภาพเส้นที่เจ้าของบัญชีวาดเก็บในประวัติ การออกหนังสือจริงใช้ไฟล์ PDF จากเจ้าหน้าที่ ฝ่าย HR ตรวจสอบข้อมูลเงินเดือน อำนาจลงนาม และแบบหนังสือของหน่วยงานตามขั้นตอนของตน ระบบไม่ได้ดึงเงินเดือน สัญญา หรือทะเบียนบุคลากรจากมหาวิทยาลัยโดยอัตโนมัติ

## วิธีเปิดด้วย Visual Studio Code

เลือก **File → Open Folder** แล้วเปิดโฟลเดอร์ `RMUTI-HR-MIS` ที่แตกจาก ZIP หากมี Python ให้เปิด Terminal ที่โฟลเดอร์นี้ แล้วใช้คำสั่งบน Windows

```powershell
py -m http.server 8000 --bind 127.0.0.1 --directory web
```

บน macOS หรือ Linux ใช้ `python3` แทน `py` เปิด `http://127.0.0.1:8000/` แล้วกด Ctrl+C ใน Terminal เมื่อต้องการหยุด วิธีนี้ใช้เฉพาะเครื่องของผู้ทดลอง ใช้ที่อยู่และพอร์ตเดิมเพื่อเรียกข้อมูลทดลองเดิมอีกครั้ง ตัวอย่างที่เปิดจากไฟล์และจาก localhost จะเก็บข้อมูลคนละชุด

## ไฟล์ที่ใช้แก้ระบบ

| ไฟล์ | หน้าที่ |
| --- | --- |
| `web/index.html` และ `web/styles.css` | หน้าเริ่มต้น รูปแบบหน้าจอ สี การแสดงผลมือถือ และแบบพิมพ์ A4 |
| `web/model.js` | เมนู ประเภทคำขอ สถานะ ตัวเลือกตำแหน่ง และข้อมูลสมมติของวิทยาเขต |
| `web/views.js` | หน้าบุคลากร แบบฟอร์ม ตาราง คิว HR กล่องรายละเอียด และใบรับคำขอ |
| `web/app.js` | การเปลี่ยนหน้า ตรวจแบบฟอร์ม บันทึก ลายเซ็น ดาวน์โหลด และการพิมพ์ |
| `web/data.js` | การอ่านและเขียนข้อมูล ทั้งโหมดทดลองและโหมด Supabase |
| `web/config.js` | โหมดระบบ Project URL, Publishable key และข้อมูลติดต่อ/ลิงก์ที่หน่วยงานรับรอง |
| `web/vendor/` | Supabase JS 2.57.4 ฉบับเบราว์เซอร์ที่แนบในชุด พร้อมประกาศสิทธิ์ของไลบรารี |
| `supabase/` | SQL สร้างระบบ ส่ง PDF แบบส่วนตัว ข้อมูลสังกัดตัวอย่าง และตัวอย่างเพิ่มบัญชี |
| `docs/SUPABASE-GITHUB-TH.md` | วิธีเตรียมฐานข้อมูล ตั้งสิทธิ์ ทดสอบสองบัญชี และเก็บโค้ดใน GitHub เมื่อพร้อม |

เทคโนโลยีหน้าบ้านเป็น HTML, CSS และ JavaScript แบบไฟล์สถิต จึงแก้ใน VS Code และเปิดใช้ชุดทดลองได้โดยไม่ต้องติดตั้ง Node.js หรือสั่ง build เมื่อเปลี่ยนเป็นโหมดเชื่อมฐานข้อมูล ใช้ Supabase Auth, PostgreSQL และ Storage ผ่าน SDK ที่แนบมา
